# 锚点核验协议

## 机器核验的四道门

`python scripts/anchor_verify.py spec.json source.md --log --write-back`

| 门 | 条件 |
|---|---|
| 基准可读 | 原文件存在、可解析且抽取文本非空 |
| 有真实匹配 | 至少一个断言锚点或来源引句通过定位 |
| 覆盖率 | `verified / total >= 0.90` |
| 零未通过 | 所有未标为 AI 补充的条目均通过；结构不为空 |

分母 `total` 是 **全部 `frames[].claims[]` + 全部 `sources[]`**。显式 `ai_only: true` 的断言仍在分母内，不计入分子；其状态为 `ai_only`，不算伪装成来源的 `failed`。因此允许的无来源补充最多占总条目的 10%。大量补充不能靠少量正确来源“洗白”。未标记 AI 补充的任何一条失败，即使覆盖率超过 90%，也会被阻止。

失败退出 **10**，不得当作最终成果交付；修正锚点、删除断言，或明确标记少量 AI 补充后再核验。AI 补充必须无 `anchor` 和 `source_id`，不能一边宣称无来源一边挂假锚点。

## 定位规则

- TXT/Markdown：严格 UTF-8（接受 BOM、CRLF）。PDF：可选 pypdf 抽取文字；不含 OCR。加密、扫描空文本、损坏文件都失败。
- 使用 Unicode NFKC 与空白归一化；不作模糊相似匹配、不忽略标点、不使用模型“猜测”原文。
- 锚点至少 4 个非空白字符。推荐引用完整一句或足够上下文，避免单个术语作为证据。
- 来源提供行号或段落 ID 时，在该范围内匹配；两者都有时必须相互一致。PDF 行号指抽取文本行号，不是假称原 PDF 的排版行号。
- 断言的 `source_id` 必须引用已通过的来源，其锚点同时存在于该来源引句和完整源材料。
- 每个命中均检查左邻的“没 / 未 / 无 / 不 / 并非 / 不是 / 不能 / not / never / without / no”。全部命中都紧邻否定词则拒绝，要求扩大引句。这是保守启发式，可能误报，也不能覆盖所有语言和远距离否定。

## 机器不能代替的走查

逐条比较 **断言含义与完整源上下文**：是否换了主语、倒置因果、扩大范围、遗漏条件，或把反例当结论。脚本不做语义蕴含验证，不保证报告“零幻觉”。

核验计数直接覆盖 claims 与 sources；正文、标题、探测答案及设计依据里的事实需要作者登记或人工检查。不得把新事实藏到 body 或 rationale，绕开分母。`body` 的每条事实必须能映射到 claims；探测中的故意错误仅作为明确标注的题面。

## 回填与失效

`--write-back` 给每条条目写入 `verified` 与 `verification_status`，给 spec 写入完整结果、源文件 SHA-256、规范化 spec SHA-256。渲染器独立计算 spec 哈希，并检查源文件当前字节哈希；内容改变、原材料路径失效，全部降为可见草稿并将断言标红。移动目录后先重新核验，再渲染。

哈希用于发现内容变更，不是签名或防篡改认证。拥有 spec 写权限的人可以伪造结果；交付验收必须亲自重跑核验。

核验器不导入规划器、渲染器或它们的校验代码，避免生成和定位共享同一个实现错误。JSONL 台账默认写到 spec 同目录的 `spec.verification.jsonl`；`--log 路径` 可指定位置。
