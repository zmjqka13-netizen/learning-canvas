# FLOW：切帧与探测设计

本文件是本技能的操作约定，不把“3–5 帧”或 FLOW 全流程声称为已经实证验证的普遍学习定律。

## 帧判定的四条硬规则

1. **必要**：删掉这一帧后，学习者将无法回答一个核心问题，或会产生一个具体误解。`why` 必须写出这个反事实。
2. **最小**：一帧回答一个问题。若两个子命题各自可独立解释，应拆分；若删掉其中一个完全不损失骨架，应合并或删除。
3. **可检验**：能设计出区别“知道这帧”和“不知道这帧”的题目；不以背诵标题代替理解。
4. **可追溯**：每条事实陈述登记在 `claims`，锚点能定位到原文；明确边界、条件和否定，不能为凑帧数添加事实。

## 切帧的四个动作

1. 列核心问题，提取原文中的机制、因果、适用条件、反例与边界。
2. 以问题分组，合并同义内容，把例子放回它解释的机制下。
3. 做删除实验：逐帧写“删去后无法…… / 容易误以为……”。没有明确损失就继续压缩。
4. 校准成 3–5 帧。材料不足时缩小报告目标；过多时分成多份报告，不能把无关知识硬塞进同一帧。

## F 自检

- 每个标题对应一个可回答的问题；帧之间互补，避免同义重复。
- `body` 中每条事实都有对应 `claims` 记录；正文徽标 `{S1}` 指向有效来源。
- 锚点保留限制词、比较对象、主语和否定；行号与段落 ID 来自 `.flow-index.json`。
- 未把“原文中有这几个字”误判成“原文支持这个结论”。机器只能做前者。
- 在 P2 把清单、不可约简理由和代表性断言给用户确认粒度。

## 有损探测

至少一题。`lossy_perturb.py` 默认生成可复现的 **drop**：保留其他帧断言，遗漏目标帧。润色可以改措辞，不能偷偷补回目标帧。

也可在 spec 中人工设计：

- `swap`：交换因果或先后关系，让学习者定位改动。
- `overgeneralize`：移除一个必要条件，让结论被错误推广。

题面须清楚标为有损或错误版本，问“丢失什么、会引起什么误解”；答案需指出目标帧与损失，不能只说“不完整”。每题只集中测试一种损失。答案折叠，先留独立作答空间。

## 自己的话

不代写、不改写学习者的复述。离线 HTML 留空并提供“漏帧 / 新增”自评区；无模型调用，也不自动判读语义。如果学习者把复述发回对话，代理只按原文指出漏掉的帧及新增的无依据说法，不提供润色后的代答。
