# 学习画布 · Learning Canvas

把一个主题、一篇文章、一份 PDF、一章笔记，或者只是一个问题，锻造成一份
**单文件交互式 HTML 学习报告**。

它不产出「一份解释」。它产出**一份「你学会了」的证据链**。

---

## 第零条 · 第一原理

> **学习效果 > 报告好看。**

HTML 再精致，如果**帧切错了**（结构本身有问题）或**断言没有来源**（可能是编的），
这份报告就是废的，本次作废、回退重做。任何时候在「做得漂亮」和「做得对」之间
有冲突，选做得对。

---

## 0. 该不该用（闸门）

先判断，不要无脑启动：

| 用户情况 | 怎么做 |
|---|---|
| 只要**一个事实**（「X 是哪年发明的」） | 直接答，**别用**本技能 |
| 材料 < 约 5k token 且只想「解释一下」 | 直接讲，**别用**本技能（收益为负） |
| 要**逐字引用**的原文摘要（法律/医疗/合规） | 走 `pdf` 技能或直接读文件 |
| 想**真的学会 / 要讲给别人 / 要能复盘** | ✅ **用本技能** |

判断依据是**意图**，不是材料长短：想「知道」→ 直答；想「掌握」→ 锻造。

---

## 1. FLOW 循环（脊柱）

四阶段，顺序不能乱：

| 阶段 | 做什么 | 一句话判据 |
|---|---|---|
| **F · Frames 帧** | 把材料压成 3–5 个最小知识单元 | **删掉任一帧，理解会塌** |
| **L · Lossy Probe 有损探测** | 先给一个有损版本，让学习者找出损失 | 能**定位损失** = 抓住了骨架 |
| **O · Own-Words 自己的话** | 学习者重述，系统只标「漏帧」与「新增」 | **「你新增的」暴露隐性误解** |
| **W · Walk-through 走查** | 生成 HTML，每条断言带可核验锚点 | 每个结论**都能追溯回原文** |

**脊柱一句话**：用「不可再压缩」定义理解，用「有损探测」测量理解，
用「自己的话」暴露误解，用「可验证锚点」防止幻觉。

> 📖 **动手设计帧 / 设计探测题之前，先读 `references/flow_framework.md`**
> —— 那里有帧判定的四条硬规则、切帧的四个动作、F 阶段自检清单、有损探测设计规则。

---

## 2. 工作流（逐阶段 + 交互检查点）

**强制停顿点只有两个：P2 与 P7**；其余阶段全自动，不要频繁打断。
P4 是**条件停顿**（仅当用户在交互现场时邀请他先口述，不阻塞流程）。

| 阶段 | 做什么 | 检查点 |
|---|---|---|
| **P0 判定** | 走 §0 闸门 | 🔸 不该用则直接答，不启动 |
| **P1 摄取** | 跑 `flow_plan.py` 建源索引（每段一个可寻址 id 与行号），再读材料 | — |
| **P2 切帧 (F)** | 产出 3–5 帧 + 每帧的不可约简理由 + 每条断言的锚点 | 🔸 **必须问**：把帧清单给他确认粒度 |
| **P3 设计探测 (L)** | 跑 `lossy_perturb.py` 生成有损探测题，再润色成通顺段落 | — |
| **P4 留白 (O)** | **不代替用户回答**。练习区由渲染器生成，内容留给用户自己填 | 🔸 条件：用户在场时邀请先口述 |
| **P5 生成 HTML (W)** | 写 spec JSON → 跑 `render_report.py` | — |
| **P6 自检门** | 跑 `anchor_verify.py`（带 `--write-back` 后再渲染，未核验项才会标红） | 🔸 **未达标（退出码 10）→ 不许交付**，回退重修 |
| **P7 交付** | 给出 HTML 路径 + 覆盖率；跑 `schedule.py plan` 给复习排期 | 🔸 **必须问**：要不要排期 |

## 3. 生成 HTML（硬约束：必须走脚本）

**禁止手写 HTML。** 必须：

1. 把内容写成 `learning_spec.json`（结构见 `assets/report_spec.schema.json`）
2. 跑渲染器：

```bash
python scripts/render_report.py learning_spec.json --out report.html
```

渲染器把 spec 注入固定模板，产出单文件 HTML（内联 CSS/JS、零 CDN）。

**为什么不让模型直接写 HTML**：

| | 手写 HTML | spec + 模板（必须） |
|---|---|---|
| 语法 | 常漏闭合标签 | 模板固定，不会错 |
| 一致性 | 每次结构不同 | 结构恒定，可复现 |
| 输出量 | 模型要输出整份 HTML | 只输出结构化 JSON，输出量显著更小 |
| 可校验 | 没法机械检查 | spec 可校验、HTML 可验锚点 |

把「HTML 生成」从创造性任务降级为确定性任务——确定性的活交给脚本。

**行内标记**（仅限三种，写在 spec 的文本字段里）：
`**加粗**`、`` `代码` ``、`{S1}`（引用来源锚点，渲染成可点击徽标）。

**退出码**：`0` 成功 · `2` spec 不合规 · `3` 模板缺占位符。
先跑 `--dry-run` 可只校验不写文件。

## 4. 自检门（硬约束：必须跑）

```bash
python scripts/anchor_verify.py learning_spec.json 源材料.txt --log --write-back
```

核验**两类**内容的锚点是否**真能在源材料里找到**：`frames[].claims[].anchor`（断言）
与 `sources[].text`（报告里「证据锚点」章节展示的引句）。

自检门共**四道**，全过才算达标（详见 `references/verification_protocol.md`）：

1. **源材料必须真的读出来了** —— 空文件、路径打错、损坏 PDF 一律判失败
2. **至少一条内容真的能追溯回源材料** —— 一条都对不上，就没有证据链
3. **覆盖率 ≥ 90%** —— 分母是**应有来源的全部条目**（含标注「AI 补充」的），
   不是「写了锚点的那些」
4. **未通过条数 = 0**（零容忍：一条编造断言也不放行）

第 3 条的分母容易被写错，代价很大：若 `ai_only` 不进分母，「10 条断言一条锚点都不写、
只把 `sources` 引句写对」会被算成 4/4 = 100% 通过，而那份报告每条事实断言都没来源。
**不写锚点反而抬高覆盖率**，闸门就奖励了它本该拦的行为。

**未达标 → 退出码 10，不许交付**。必须回退：把找不到来源的条目改成
「AI 补充，无来源」并显式标注，或者删掉。

后两道是实测教训：源路径打错或 PDF 损坏时，零条断言被核验却被报成「覆盖率 100%，
可以交付」—— 空基准不能算满分，一条编造断言也不该被平均分放行。

脚本还会做一次**否定词检查**：若某片段在源材料中的每一处命中都紧跟着否定词
（如源文「**没**有任何一项安全保证」里取出「有任何一项安全保证」），判为疑似
削去否定、结论与原文相反。纯子串匹配抓不到这类，必须看命中处的左邻字符。

> ⚠️ **设计要点**：本脚本与渲染器**走完全独立的实现路径**，不复用其代码。
> 若核验与生成同源，同一个理解偏差会让两边一起错、一起过。

达标后加 `--write-back`，把结果写回 spec，渲染时就能标红未核验项。
**先核验再渲染** —— 反过来就没有标红效果，等于绕过了自检门。

---

## 5. 硬约束清单

1. **帧必须 3–5 个**，且每个都能通过「删了会塌」检验
2. **无来源不断言**——每条事实性断言要么有锚点，要么显式标注「AI 补充，无来源」
3. **必须至少 1 条有损探测**——没有 L 阶段就不是 FLOW，退化成普通解释
4. **AI 绝不代替用户做 O 阶段**——不代写复述、不帮他组织语言
5. **HTML 必须由脚本生成**，禁止手写
6. **报告必须自包含**（无 CDN 外链）、**可打印**（`@media print` 已内置于模板）
7. **不代做**：术语可以让用户自己先猜，不要一上来就定义

## 7. 自迭代规程

- 改进只能来自**实测暴露的问题** + 记进 `CHANGELOG.md`，不许凭感觉改
- 改完必须跑 `python tests/regression_suite.py`，**31 项全过才收工**；
  新发现的绕过手法要当场补成用例（现在拦得住的，将来改坏了也要拦得住）
- 若要改 spec 结构，必须**同步**改 `report_spec.schema.json` 与 `render_report.py` 的校验
- 若要改版式，只改 `assets/html_template.html`，不要动渲染逻辑

**关于「验证」本身的两条纪律**（都是踩坑换来的，写在这里因为比代码更容易忘）：

1. **必须照文档描述的方式去验证**。否则测的是你脑子里的流程，不是用户会走的流程 ——
   曾经文档里那条命令链是错的（`plan.json` 被说成能直接喂渲染器），
   因为当时是在脑子里过了一遍而不是照着敲。
2. **判断「有没有某类东西」交给解析器，不交给搜索**。`grep` 数注入载荷会连
   已转义的惰性文本一起数进去，制造假警报；反过来也会漏掉真的可执行片段。
   同理，判断覆盖率要看**分母**是什么 —— 分母错了，100% 会骗人。

## 8. 附：报告会额外做两件「元层面」的事

不是装饰，是设计的一部分：

1. **内嵌「这份报告为什么这样设计」章节** —— 把 FLOW 四阶段、三理论映射、帧的切法
   直接讲给读者。评审不必读本文件，打开 HTML 就看到设计者的思考。
2. **帧正文里的锚点可点击跳转** —— 帧的正文中写 `{S1}` 会渲染成可点击徽标，点击跳到
   「证据锚点」章节对应条目；断言列表则直接显示来源片段与灰底「无来源补充」标记。
   让「可信」变成可复核的事实，而不是一句声称。
